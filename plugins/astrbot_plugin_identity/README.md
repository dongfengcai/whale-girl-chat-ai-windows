# identity — 身份注入

在每条消息前标注**谁在说话**，让模型能区分群里的不同用户。

## 解决什么问题

AstrBot 送给模型的提示词只有消息文本：

```
今天天气不错
```

模型看不出这是谁说的。群里 A 和 B 分别聊天，模型会把两人当成同一个人（只是名字不同）。

**本插件的做法**：不隔离上下文，只标注身份。

```
今天天气不错   →   （小明·群主）今天天气不错
在吗           →   （小红）在吗
```

于是机器人**既能看到整个群的对话流，又知道每句话出自谁** —— 这更接近真人在群里的状态。

## 为什么不用会话隔离

隔离（`unique_session`）也能让人分不清的问题缓解，但代价大：

| | 会话隔离 | 身份注入 |
|---|---|---|
| 区分用户 | ✅ | ✅ |
| 群聊公共视野 | ❌ **失去**（A 说的 B 问起时不知道） | ✅ 保留 |
| 群里的话题能不能接上 | ❌ 接不上 | ✅ 能 |
| 上下文数量 | 每用户一份（token 涨） | 每群一份 |

**所以推荐：关闭 `unique_session`，用本插件。** 两者也可以同时用，但没必要。

## 角色从哪来

**首选：直接从消息事件里读**（OneBot v11 的群消息事件本身就带角色）。

```json
{
  "message_type": "group",
  "sender": { "user_id": ..., "nickname": "...", "role": "owner" },
  ...
}
```

| role 值 | 显示 |
|---|---|
| `owner` | 群主 |
| `admin` | 管理员 |
| `member` | 成员 |

普通成员**也标注**「成员」，不是省略 —— 这样模型才知道「这是个普通群友」，
从而和群主/管理员区别对待。不标的话它无从判断对方是不是管事的。

**兜底：调接口**（`get_group_member_info`）。有些适配器可能不在事件里带角色，
这时才需要一次接口往返。

**最终兜底：只标注名字**。无论哪一步失败，消息都必须能正常处理。

## 两个踩过的坑

### ① 空结果不能缓存

```python
_ROLE_CACHE[key] = (time.time(), role)   # ❌ role 可能是空串
```

一次超时或接口报错如果被缓存 10 分钟，该用户接下来 10 分钟都只有名字，
**而且连「查角色失败」的日志都不会打** —— 因为压根没去查（直接命中空缓存）。

表现极具迷惑性：**某个人突然一直没角色，且毫无提示**。

修法：只缓存查到的结果，空结果不缓存，宁可每次重试。

```python
if role:
    _ROLE_CACHE[key] = (time.time(), role)
else:
    _ROLE_CACHE.pop(key, None)
```

> 通用经验：**缓存失败结果是个陷阱**。缓存的价值在于"稳定的结论"，
> 而失败是暂时状态 —— 缓存它等于把一次抖动放大成一段时间的持续故障。

### ② 异常不能静默吞掉

早期版本把所有异常都包在 `if debug:` 里面，导致"只有名字没有角色"时
**完全看不出原因**。现在无论 debug 开关，失败都会打日志，且报错信息带具体细节：

```
[identity] 查角色失败，本次只标注名字：get_platform_inst('aiocqhttp') 返回 None（已注册平台：[...]）
[identity] 查角色超时（3s），本次只标注名字。group=... user=...
```

> 「可选功能失败」不等于「可以不记录」。降级是设计，但**为什么降级**必须可见，
> 否则排查时只能靠猜。

## 三个必须处理好的问题

**① 不能每条消息都查**

一次接口往返几十到几百毫秒，会让回复变慢，2GB 机器更吃紧。所以按「群×用户」缓存，
默认 10 分钟。代价：群里有人被升降权限，最多延迟 10 分钟才反映出来。

**② 查询可能失败**

NapCat 没响应、机器人权限不足、用户已退群 —— 都会失败。所以查询包了超时（默认 3 秒）
和异常兜底：**查不到就只标注名字**，绝不阻塞消息。

**③ 机器人不是管理员时可能拿不到**

同样退化为只标注名字，不会报错。

## 活跃度

平台接口**不提供**这个，只能本地统计。

插件记录「群×用户」的发言时间戳，滑动窗口（默认 72 小时）内发言数达到阈值
（默认 10 条）就标记「活跃」。

**状态在内存里，重启即清零** —— 这是有意为之：活跃度是短期信号，不值得为它引入落盘开销。

⚠️ 默认**关闭**，因为它每轮都要重新发一遍，会增加 token 消耗。

## 配置项

| 项 | 默认 | 说明 |
|---|---|---|
| `enabled` | `true` | 总开关 |
| `include_name` | `true` | 注入发送者名字。关了就分不清谁在说话 |
| `include_role` | `true` | 注入群角色 |
| `include_group` | `false` | 注入群名 |
| `include_activity` | `false` | 注入活跃度（吃 token） |
| `activity_window_hours` | `72` | 活跃度统计窗口 |
| `activity_min_messages` | `10` | 判定活跃的最少发言数 |
| `role_cache_minutes` | `10` | 角色缓存时长 |
| `query_timeout_seconds` | `3` | 查询超时，超时退化为只用名字 |
| `name_max_length` | `12` | 名字截断长度 |

### token 消耗的取舍

标签**每轮都要重发**，标签越多越贵：

| 组合 | 提示词前缀 | 相对消耗 |
|---|---|---|
| 仅名字 | `（小明）` | 基准 |
| 名字+角色 | `（小明·群主）` | +约 3 token |
| 名字+角色+活跃 | `（小明·群主·活跃）` | +约 5 token |

单看不多，但每轮都发。**建议先只开「名字+角色」**，跑几天看余额消耗再决定。

## 配套人设

光注入身份不够，**人设必须告诉模型"这些标签是什么意思"**，否则它还是会混。
在后面「配套人设」一节有可以直接粘贴的段落。

## 与其它插件的关系

本插件用 `on_llm_request` 钩子改**提示词**，**不碰消息链**。所以和另外几个插件不冲突：

| 插件 | 改的东西 |
|---|---|
| poke_react | 消息链 + `message_str` + 唤醒标志 |
| media_pacer | 消息链（过滤媒体） |
| reply_arbiter | 事件传播（仲裁） |
| balance_guard | 事件传播（拦截） |
| **identity** | **`req.prompt`（最终提示词）** |

各改各的，互不干扰。

## 日志

```
[identity] 启动：注入 名字+角色，角色缓存 10 分钟
[identity] 注入 -> （小明·群主）今天天气不错
[identity] 查角色超时（3s），只用名字
```

调试时把 `debug` 打开，能看到每次注入的完整前缀。

## 边界情况

| 情况 | 行为 |
|---|---|
| 私聊 | 只标注名字（没有群角色） |
| 查角色超时/失败 | 退化为只标注名字，不阻塞 |
| 拿不到昵称 | 用 QQ 号代替 |
| 昵称超长 | 截断到 `name_max_length` |
| 机器人非管理员 | 部分字段可能查不到，退化为名字 |
| 同一请求被处理两次 | 检测到已有前缀则跳过，不重复注入 |
| 用户退群 | 接口失败，退化为名字 |
