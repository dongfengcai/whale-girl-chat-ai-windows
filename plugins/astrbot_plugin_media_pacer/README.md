# media_pacer — 媒体节流与过滤

对应**需求 4 和 5**：

- **需求 4**：能识别图片，但识别要有间隔，且不能影响纯文字消息和 API 调用
- **需求 5**：不识别语音和视频，非文字非图片的消息直接跳过

## 需求 5：消息类型过滤

| 消息类型 | 处理 |
|---|---|
| 纯文字 | ✅ 正常送 LLM |
| 图片 | ✅ 送 LLM（受下面节流约束） |
| **语音** | ❌ 直接跳过，不回复 |
| **视频** | ❌ 直接跳过，不回复 |
| 文件 | ❌ 直接跳过 |
| 表情 / 戳一戳 / 红包 / 位置 等 | ❌ 直接跳过 |
| 文字 + 图片混合 | ✅ 送 LLM（按"含图片"处理） |
| 文字 + 语音混合 | ⚠️ **只取文字部分**送 LLM，语音丢弃 |

**关键设计**：「跳过」指的是**不送进 LLM**，而不是报错或回复"我不支持"。
静默丢弃 —— 机器人对语音视频视而不见，符合"像真人"的定位（真人也不会对每个表情都回应）。

最后一种情况值得说明：如果一条消息是「文字 + 语音」，直接整条丢弃会显得机器人
"没听见"用户在说什么。所以**提取文字部分**送去理解，语音部分忽略。

## 需求 4：图片识别节流

### 为什么需要节流

图片走的是 `deepseek-flash` 的视觉通道，**比纯文字贵得多**（一张图可能相当于几千个
输入 token）。群聊里如果有人连发十张图，既烧钱又拖慢响应。

### 节流策略：令牌桶

```
每个会话（群 / 私聊）独立一个桶

桶容量 capacity = 3        ← 最多允许 3 张图连续通过
补充速率 refill_seconds = 20  ← 每 20 秒恢复 1 个令牌
```

行为：

| 场景 | 结果 |
|---|---|
| 第 1 张图 | ✅ 立即识别（消耗 1 令牌） |
| 紧接着第 2、3 张 | ✅ 立即识别（桶空了） |
| 第 4 张 | ⏳ 桶空 → 按配置处理（见下） |
| 20 秒后 | 桶恢复到 1，下一张图可识别 |

### 超限时的两种模式

配置项 `on_exceeded`：

| 值 | 行为 | 适用 |
|---|---|---|
| `skip`（默认） | 静默忽略图片，**但文字部分照常处理** | 推荐。不影响聊天流畅度 |
| `defer` | 图片进队列，等令牌恢复后延迟识别 | 想确保每张图都被看到 |

**默认 `skip` 的理由**：需求 4 明确说"这个时间留出够不影响主要的纯文字消息和调用 API"。
`skip` 模式下文字消息**完全不受影响** —— 图片被限流时，附带的文字照样回复。
`defer` 会让消息排队，反而可能拖慢后续文字消息。

### 绝不阻塞的东西（需求 4 的核心）

节流**只作用于图片理解**，以下完全不受影响：

- ✅ 纯文字消息 → 立即处理，不看桶
- ✅ LLM API 调用 → 正常并发
- ✅ 管理员指令 → 绕过所有节流
- ✅ 余额告警等系统消息 → 不受影响

实现上，节流判断在**消息进入 LLM 之前**同步完成，不引入 await 等待、不排队、不加锁。

## 配置项

| 项 | 默认 | 说明 |
|---|---|---|
| `enabled` | `true` | 总开关 |
| `skip_voice` | `true` | 跳过语音（需求 5） |
| `skip_video` | `true` | 跳过视频（需求 5） |
| `skip_file` | `true` | 跳过文件 |
| `skip_other` | `true` | 跳过表情/戳一戳等其它类型 |
| `image_capacity` | `3` | 令牌桶容量 |
| `image_refill_seconds` | `20` | 每多少秒恢复 1 个令牌 |
| `on_exceeded` | `skip` | `skip` 或 `defer` |
| `per` | `session` | 令牌桶粒度：`session`（每群/每人独立）或 `global`（全局共享） |
| `bypass_admin` | `true` | 管理员不受节流限制 |
| `max_image_mb` | `5` | 超过此大小的图片不识别（省带宽，3Mbps 下尤其重要） |

`per: session` 是默认值 —— 某个群刷图不会影响其它群。

## 带宽考量（3 Mbps 服务器）

每张图都要**下载到服务器**才能送去识别，所以图片大小直接影响带宽：

- 一张 200 KB 的图，3 Mbps 下约需 0.5 秒
- 三张连续 → 1.5 秒，这期间文字消息的收发会受影响

`max_image_mb: 5` 与令牌桶共同作用，把图片带来的带宽压力限制在可控范围。
