# poke_react — 戳一戳回应

让机器人对**戳一戳**有反应，并且把戳一戳**视为与 @ 一致**，参与需求 7 的多人仲裁。

## 处理流程

```
收到消息
    │
    ▼
优先检查是不是戳一戳（priority=1100，最早）
    │
    ├─ 不是 → 原样放行，什么都不做
    │
    └─ 是，且戳的是自己
            │
            ▼
      改写消息链：
        Poke 段  →  注入 At(自己)   ← 让 @ 检测原样生效
        Poke 段  →  追加文字提示     ← 模型需要知道发生了什么
            │
            ▼
      交给后续插件与 LLM 正常处理
```

## 为什么群聊必须手动置唤醒标志（踩过的坑）

**现象**：私聊戳一戳正常，**群聊戳一戳没反应**。

根因在 AstrBot 的 `WakingStage`（`waking_check/stage.py`）—— 它的唤醒判定
**私聊和群聊是两套完全不同的逻辑**：

```python
# 群聊：扫描消息链，必须找到 At(自己) / AtAll / 引用自己
for message in messages:
    if isinstance(message, At) and str(message.qq) == str(event.get_self_id()):
        is_wake = True
        event.is_at_or_wake_command = True
        break

# 私聊：无条件唤醒
if event.is_private_chat() and not self.friend_message_needs_wake_prefix:
    is_wake = True
    event.is_at_or_wake_command = True
```

于是：

| | 私聊 | 群聊 |
|---|---|---|
| 唤醒条件 | **无条件**，任何消息都算唤醒 | 必须检测到 At / AtAll / 引用 |
| 戳一戳能否唤醒 | ✅ 能（**与注入 At 无关**） | ❌ 不能 —— 判定时消息里还没有 At |
| `message_str` 是否为空 | 是（需要改写） | 是（需要改写） |

**关键点**：`WakingStage` 在本插件的 handler **之前**就执行完了。等我的插件
往消息链里注入 At 时，唤醒判定早就做完了 —— **事后注入对唤醒无效**。

所以本插件必须**直接把标志位置上**，不指望它重新检测：

```python
event.is_at_or_wake_command = True
event.is_wake = True
```

> 通用经验：**注入结构 ≠ 改变已算好的状态。** AstrBot 的流水线里，很多标志位
> 是在早期阶段一次性算好并缓存的（唤醒判定、`message_str` 都是如此）。
> 插件在中后期改写消息内容时，**必须同时把这些派生状态一起改掉**，否则会出现
> "看起来改了但系统不认"的情况。

## 一次戳一戳，插件改写了三样东西

| 改写对象 | 用途 | 不改的后果 |
|---|---|---|
| `message_obj.message` | 消息链：消息类型过滤、其它插件 | 被 media_pacer 当垃圾丢掉 |
| **`message_str`** | **LLM 提示词的来源** | 提示词为空，模型不回复 |
| **`is_at_or_wake_command` / `is_wake`** | **群聊的唤醒判定** | 群聊根本不调 LLM |

前两个是"喂什么给模型"，第三个是"要不要叫模型"—— **缺一不可**。

## 为什么必须同时改写 `message_str`（踩过的坑）

**只改消息链是不够的。** AstrBot 构造 LLM 提示词时取的是 `event.message_str`，
不是消息链本身：

```python
# astrbot/core/astr_main_agent.py
req.prompt = event.message_str[len(config.provider_wake_prefix):]
```

而 `message_str` 是消息**进来时**由原始消息算好的，之后改消息链**不会**让它更新。

戳一戳**没有文字**，所以 `message_str` 是空串 —— 结果就是：

| 只改消息链 | 同时改 message_str |
|---|---|
| 插件日志正常打印"触发回应" | 同左 |
| 消息链里有 @ 和文字 | 同左 |
| **送给模型的提示词是空的** | 提示词是那句旁白 |
| **模型不回复** | 模型正常回复 |

这个故障很隐蔽：**日志看起来一切正常，但机器人就是不说话**。因为它不是"插件没跑"，
而是"跑对了但喂给模型的内容是空的"。

所以本插件做两件事：

```python
event.message_obj.message = new_chain   # 消息链：用于唤醒判定、被其它插件看到
event.message_str = note                # 提示词：AstrBot 真正喂给模型的东西
```

> 通用经验：**AstrBot 里有两条并行的消息表示** —— 消息链（`message_obj.message`）
> 和纯文本（`message_str`）。插件改写消息内容时，**两个都要改**，否则会出现
> "看起来改了但模型没收到"的情况。

## 与需求 7 的兼容

**关键设计：不修改 `reply_arbiter` 一行代码。**

不在仲裁插件里加"戳一戳特判"，而是把戳一戳**转换成结构上真正的 @**（注入 `At` 组件）。
于是 `reply_arbiter` 现有的这套逻辑**原样生效**：

| reply_arbiter 的逻辑 | 戳一戳场景下的行为 |
|---|---|
| `_mentioned()` 检测 @ | ✅ 检测到注入的 At，视为被唤醒 |
| 合并窗口（默认 2000ms） | ✅ 戳一戳与被 @ 一起参与窗口合并 |
| 优先级判定（谁在上下文中） | ✅ 戳一戳的发起者按同一规则参与 |
| 只放行优先级最高的那条 | ✅ 多人同时戳 + @ 时只回一次 |

这也符合语义 —— **戳一戳本来就是"点名找某人"**，与 @ 同类。

## 优先级顺序（重要）

四个插件的执行顺序：

| 插件 | priority | 作用 |
|---|---|---|
| **poke_react** | **1100** | 最先，把 Poke 转成 At + 文字 |
| media_pacer | 1000 | 过滤媒体、图片限流 |
| reply_arbiter | 998 | @ 仲裁 |
| balance_guard | 999 | 余额/额度拦截 |

**poke_react 必须排在 media_pacer 之前**（1100 > 1000），因为 media_pacer 会把
`Poke` 当成"其它类型"从消息链里移除。一旦被它先处理，戳一戳就永远看不到了。

## 为什么必须附带文字

戳一戳是**没有文字**的。如果只注入 At 不注入文字，会有两个问题：

1. **media_pacer 会拦掉整条消息** —— 它判断"没有实质内容"（既无文字也无图片）就静默忽略
2. **模型不知道回什么** —— 一条纯 @ 没有语义，模型只能瞎猜

所以注入一句可配置的描述（默认「有人戳了你一下」），模型再按人设演绎反应。
配合人设里的傲娇/慵懒设定，效果通常是被戳了会有点小情绪。

## 配置项

| 项 | 默认 | 说明 |
|---|---|---|
| `enabled` | `true` | 总开关 |
| `reaction_text` | `有人戳了你一下` | 转成文字喂给模型。**这是唯一影响回复内容的项** |
| `inject_at` | `true` | 注入 @ 标记以参与仲裁。关闭则戳一戳不参与仲裁 |
| `cooldown_seconds` | `5` | 同一会话的冷却，防止被连戳导致刷屏和烧 token |
| `only_when_poked` | `true` | 只响应戳自己；关闭则任何戳一戳都回应 |
| `debug` | `false` | 打印忽略原因等调试日志 |

### `reaction_text` 可以怎么写

它只是一句**给模型看的旁白**，模型会按人设自然回应。所以写法可以带点情境：

| 写法 | 效果 |
|---|---|
| `有人戳了你一下` | 中性，模型自由发挥 |
| `有人戳了戳你的脸` | 模型更容易给出傲娇反应 |
| `有人戳了你一下，你很困` | 更容易触发慵懒设定 |

**不要**在这里写完整的回复内容 —— 那是人设的职责，这里只提供"发生了什么"。

### 冷却时间的取舍

戳一戳在 QQ 里很容易被连点。`5` 秒能挡住连点，又不会让正常互动显得迟钝。

想完全禁止刷屏可以调大；想让它每次都回应就设 `0`（但要接受被连戳时
每次都调一次 API，烧 token）。

## 关于目标判定

只响应「戳自己」时，用的是官方推荐的 `Poke.target_id()`（源码里 `qq` 字段已
标记 deprecated），并回退到 `id` / `qq` 字段以兼容不同 AstrBot 版本。

如果日志里发现戳自己没反应，把 `debug` 打开看这行：

```
[poke_react] 忽略戳向他人：target=xxx self=yyy
```

`target` 和 `self` 不相等说明目标字段解析不对，把日志发出来。

## 日志

```
[poke_react] 启动：戳一戳视为 @，参与仲裁，冷却 5 秒
[poke_react] 戳一戳 -> 触发回应 group:123456 user:789（已注入 @）
[poke_react] 123456 冷却中，忽略
```

## 边界情况

| 情况 | 行为 |
|---|---|
| 别人戳别人 | 忽略（`only_when_poked` 开启时） |
| 连续戳 | 冷却期内忽略 |
| 戳一戳 + 附带文字 | 保留原有文字，追加提示语 |
| 戳一戳 + 图片 | 图片照常处理，另加提示语 |
| 一条消息多个 Poke | 只处理第一个命中的，其余丢弃 |
| 关闭 `inject_at` | 仍然会回应，但不参与 @ 仲裁 |
